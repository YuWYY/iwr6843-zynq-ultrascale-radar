# 持续采集和滚动显示：实板验证完成

当前应用为 `M2-SW4.1-v1.6 / 20261030_live_dp_01`。程序已恢复并保持 `LIVE`，用户确认“LIVE 正常，编号和图像持续更新”。当前仍使用已验证的有限源单帧采集流程，持续重复采集，不再到 16 或 32 帧自动结束。

## 当前操作

串口 COMx、115200。无需重新点击 Vitis Run。

| 命令 | 行为 |
|---|---|
| `scope stop` | 完成正在处理的有限帧后暂停，保留最后有效图像 |
| `scope live` | 从正常暂停状态恢复持续采集 |
| `scope status` | 查看 LIVE、暂停状态及最新采集编号 |
| `display status` | 查看显示状态和错误计数 |
| `scope data 127` | 暂停后导出历史区第 128 个条目的距离谱 |

`HISTORY 128/128` 表示历史区已满，此后保持 128 个条目并丢弃最早一帧；`SESSION` 继续增加。上图更新最新帧，下图按真实时间戳显示最近的历史。`CAPTURE RATE` 是可见历史窗口的平均采样频率，包括窗口内的暂停间隔；显示器刷新仍是 60 Hz。

正常暂停可直接 `scope live` 恢复，包括首帧开始前、两帧之间及完整帧保留状态。异常显示 `FAILED` 时保留现场并检查原因，不自动重试。开机仍为 SAFE，首次采集需原有预检；本轮没有增加上电自动发射。

## 实测结果

- 第一段连续接受 **132 帧**，跨越原 16/32 帧上限和 128 帧历史容量。
- 第一段时间跨度 **183.607420 s**；相邻帧 **1.401501～1.402916 s**，平均 **0.71348 帧/s**。
- 暂停时导出的完整 128 条历史对应 **session 5～132**，编号、时间戳、频谱、CRC 关联均一致。
- 主动发送 `scope stop` 后，3 秒观察窗内没有新帧；随后保存历史，发送 `scope live` 后继续接受 4 帧。
- 用户报告“突然停止”发生在这次人工暂停核验期间。日志记录暂停空隙 **38.509855 s**；不是程序达到某个固定帧数自动结束。之后只读观察又收到 **session 175～179**，状态 `LIVE active=1 stop=0 live=1`。
- DPDMA ISR/EISR 错误为 0；TX FIFO 观察计数前后均为 1，保留启动期事件。已记录的实采帧无 ADC 削顶。
- 验证脚本结束时释放串口并保持持续采集，没有再次发送停止命令。

## 修改和验证范围

只修改应用入口、版本、采集调度器和显示标注。DSP 算法、原生捕获状态机、DMA、DP 驱动、采集 cfg、RTL、PL bit、XSA、平台/BSP、FSBL 均保持上一成功版本。新增的 LIVE 模式每次仍执行现有预检、完整采集、停止源、DMA 清理、HSI/CRC 检查和显示确认。

LIVE 内部准备阶段不重复绘制未变化的图像；只有有效新帧和可见状态变化触发显示更新。正常运行没有固定帧数终点；计数饱和不会误触发完成，原生 session 耗尽仍按门槛停止。

原生构建和 ELF 内存分区检查通过；7 项构建工具检查通过。调度器严格编译和 UBSan 测试覆盖 160 帧滚动、显示确认、有限模式兼容、CRC、身份、错误停止、计数边界及各暂停位置的恢复。LIVE/STOPPED 布局已用生产绘图代码和真实数据复绘检查。主机测试与实板证据分别保存。

本轮证明了几分钟持续更新、128 帧滚动及一次实板暂停恢复；不代表长期运行或多次冷启动已经验收。当前是带帧间空隙的连续重复采集，尚未升级为无间断高速 LVDS 流。测距标定、静态背景处理、目标识别仍属后续工作。
